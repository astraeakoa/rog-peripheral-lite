# 宏导入与导出（v0.3.1）

“导入”读取到当前编辑器，不立即覆盖已保存的槽位，也不改写鼠标。检查步骤后点击“保存”。“导出”导出当前编辑内容，可包含未保存的修改。解析失败时保留原编辑内容。

编辑器仅提供 `Down`、`Up`、`Delay`。Down / Up 的 Milliseconds 是动作执行前的等待，范围 0–60000 ms；Delay 则只等待指定时间（1–60000 ms），不额外等待两次。例如 `Down LButton 0 → Up LButton 50` 表示按住左键约 50 ms 后松开。选中下一条步骤后点击“插入”，可在任意两条步骤之间添加动作。

旧配置和导入文件中的点按 `Press` 会展开为相邻的 `Down`、`Up`，原等待放在 Down 前。编辑器优先把动作前的独立 Delay 合并到该动作的等待栏，合并后超过 60000 ms 的等待及末尾 Delay 保持独立。JSON / CSV 保留每行 Milliseconds；AHK / GMAC 导出为动作前的 Sleep / Delay，保持事件顺序与等待时长。旧版程序不会执行 Down / Up 行的等待，因此新文件请使用新版程序播放。

| 格式 | 支持范围 | 触发方式和次数 |
|---|---|---|
| JSON `.json` | 原生版本 1 文件；也兼容旧版单个 MacroDefinition JSON | 完整保留名称、步骤、每轮次数、触发方式、循环间隔 |
| CSV `.csv` | 表头 `Action,Key,Milliseconds`，支持引号字段 | 本程序通过首行元数据注释保留；普通 CSV 导入默认为单次、1 次、50 ms |
| AutoHotkey `.ahk` | v1/v2 直线型 `Send` / `SendInput` / `SendEvent` 与 `Sleep`，可有一个热键块 | 本程序导出时通过注释保留。外部 AHK 运行时只执行一步骤序列，不应用本程序的触发模式和重复次数 |
| Armoury Crate `.GMAC` | 文本格式的 `Press` / `Release` / `Delay`，支持已确认的左右鼠标键编码及可校验的普通键盘编码 | 仅保存步骤，导入默认单次、1 次、50 ms；末尾独立 `1` 作为固定标记，不是重复次数 |

文件最多 1 MB，最多 500 步。JSON 是本程序自定义格式，不是 Armoury Crate 格式。除下述 GMAC 子集外，不支持其他厂商专有文件或任意 XML/JSON。CSV 必须使用上述列名。

## GMAC 与鼠标按键

GMAC 支持依据用户提供的文本样本实现，不代表所有 Armoury Crate 版本或事件类型均兼容。

```text
Press,Left Click,301,301
Delay,40
Release,Left Click,301,301
Press,S,31,83
Release,S,31,83
1
```

- GMAC 的 `Press` 是按下，映射为内部 `Down`；`Release` 映射为 `Up`。内部 `Press`（点按）导出为连续的按下和松开两行。
- 鼠标只支持 `Left Click,301,301` 和 `Right Click,302,302`。宏编辑器、JSON、CSV、AHK 使用 `LButton` / `RButton`；不支持中键、侧键、滚轮及鼠标移动。
- 普通键盘事件按名称、扫描码和 Windows 虚拟键码交叉校验；扫描码必须符合当前 Windows 键盘布局。暂不导入/导出扩展扫描码、媒体键等未经样本确认的编码；未知事件或冲突编码会报错，不会跳过。
- 要求末尾独立一行 `1`，导出时原样保留。它的厂商语义未确认，本程序不把它解释为次数或触发模式。
- 接受 UTF-8 BOM、CRLF/LF 与末尾空行；0 毫秒等待作为无操作移除，其他延迟须为 1–60000 毫秒。按下/松开必须配对。
- 导出 UTF-8 无 BOM、CRLF 换行；不写入自定义元数据。名称、每轮次数、触发方式和循环间隔不存入 GMAC，界面导出时会提示。需要完整备份请使用 JSON。
- GMAC 导出后的事件数同样不能超过 500；点按展开后超限会拒绝导出。

停止、取消、异常及退出时，执行器尝试释放宏已按住的左右鼠标键和键盘键。左右键使用 Windows 鼠标输入事件，不使用键盘虚拟键模拟。

验证使用假输入输出，不发送实际点击。用户样本共 128 步、62 个按键事件、总延迟 14340 ms，导入后导出的事件行与原文件一致；导出文件在 Armoury Crate 中重新导入仍需实机确认。

## 触发方式

- **单次按下**：每个物理按下沿执行一轮（按“每轮次数”重复）；一直按住不会因操作系统自动连发而重复启动。运行期间的其他触发不排队。
- **连续触发**：按一下开始循环，再按同一个触发键停止。每轮之间等待“循环间隔”。
- **按住触发**：按住时循环，松开立即取消当前步骤，包括正在等待的延迟，释放已按下的键。

三种方式都可用 `Ctrl + Alt + F12`、宏面板或托盘“停止宏”中止。保存/重注册绑定、设备断开、退出程序时也会停止。需要程序常驻。按住方式依赖鼠标固件映射发出完整的 F13–F24 按下/松开事件；真实侧键行为请在目标设备中确认。

## AHK 支持的写法

```ahk
F6::
{
    Send "^c"
    Sleep 100
    Send "{Ctrl down}v{Ctrl up}"
    Sleep(50)
    Send "{Enter}"
}
```

v1 同样可写 `Send, ^c` 和 `Sleep, 100`。支持 `^ ! + #` 修饰键、`{键名}`、`{键名 down/up}`、`{键名 次数}`、`{vk41}` 等两位虚拟键码。普通字符串支持英文字母、数字、空格，大小写按 Shift 处理；其他键使用显式键名。

导入的 AHK 热键声明只作为容器识别，不会绑定原脚本热键；需在本程序中选择鼠标按键。循环/分支/函数、变量/表达式、Run、鼠标命令、Unicode 文本和高级 Send 选项不支持，解析会报错（AHK 语句包含行号）。程序从不执行导入的脚本。

AHK 导出对键盘使用显式 `vkXX`，对鼠标左右键使用 `LButton` / `RButton`（例如 `Send "{LButton down}"`），不使用鼠标移动或 Click 命令。建议传递完整配置优先使用 JSON。
